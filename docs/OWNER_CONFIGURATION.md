# OWNER CONFIGURATION — СТРОЙДОМ

Документ для будущего заказчика / владельца сайта перед переводом:

```env
SITE_MODE=production
```

Это **не** юридическое заключение. Список привязан к фактической архитектуре СТРОЙДОМ
(лендинг → `POST /api/leads` → SQLite → уведомление без ПДн в Telegram → закрытый раздел `/leads`).

Программист **не выдумывает** реквизиты, сроки, гарантии и статусы Роскомнадзора.

---

## 1. Режим сайта

| Переменная | Значения | Смысл |
| --- | --- | --- |
| `SITE_MODE` | `demo` (по умолчанию) / `production` | В `demo` публичная форма **не сохраняет** ПДн. В `production` заявка пишется в БД только при полной legal-конфигурации и `consent=true`. |

`SITE_MODE` не является секретом.

---

## 2. Обязательные сведения оператора (production)

Заполняются владельцем (env / юридические страницы подтянут значения):

| Переменная | Назначение | Примечание |
| --- | --- | --- |
| `LEGAL_OPERATOR_NAME` | Наименование / ФИО | Обязательно для production |
| `LEGAL_OPERATOR_STATUS` | Правовой статус (`ooo`, `ip`, `self_employed`, `individual`, `other`) | Не все статусы требуют ОГРН |
| `LEGAL_INN` | ИНН | Обязательно для production gate |
| `LEGAL_OGRN` | ОГРН / ОГРНИП | Если применимо к статусу |
| `LEGAL_ADDRESS` | Юридический / почтовый адрес | Для политики |
| `LEGAL_EMAIL` | Официальный email | |
| `LEGAL_PHONE` | Официальный телефон | |
| `PRIVACY_CONTACT_EMAIL` | Контакт по вопросам ПДн | Может совпадать с `LEGAL_EMAIL` |
| `PERSONAL_DATA_RETENTION_DAYS` | Срок хранения заявок (дни) | **Владелец** выбирает исходя из целей; код не придумывает срок |
| `PRIVACY_POLICY_VERSION` | Версия политики | Например `1.0` |

Технический gate: `npm run compliance:check`  
При неполной конфигурации и `SITE_MODE=production` — `TECHNICAL_COMPLIANCE_GATE=FAIL`.

---

## 3. Роскомнадзор

Владелец должен:

1. Определить, является ли он оператором ПДн по фактическому flow.  
2. Оценить необходимость уведомления Роскомнадзора / наличие оснований исключения.  
3. При необходимости подать уведомление **до** реальной обработки.  
4. Подтвердить статус письменно для своей документации.

Код **никогда** не ставит автоматически «уведомление подано».

---

## 4. Локализация

Владелец / ops подтверждают, что первичный сбор и хранение ПДн граждан РФ размещены в требуемой российской инфраструктуре, **когда это требуется**.

Указание провайдера (например Beget) в документации деплоя **не** считается само по себе юридическим доказательством — нужна явная проверка владельца.

Путь БД в типовом VPS-сценарии: SQLite вне каталога деплоя (см. `DEPLOY_BEGET.md`).

---

## 5. Внешние обработчики и трансграничность

Фактический контур СТРОЙДОМ:

| Сервис | Что передаётся |
| --- | --- |
| Telegram Bot API | В production: только ID заявки, дата, ссылка на CRM — **без** имени/телефона/комментария |
| Google Fonts (`next/font`) | Шрифты собираются на этапе сборки Next.js (self-host) |
| images.unsplash.com | Публичные изображения (не ПДн заявок) |

Владелец решает:

- оставлять ли Telegram;
- нужна ли правовая оценка трансграничности;
- каких ещё подрядчиков подключать (почта, CRM, аналитика).

Аналитика (`NEXT_PUBLIC_METRIKA_ID`) в коде **не подключена** — не включать без отдельного решения и cookie/consent дизайна.

---

## 6. Срок хранения и удаление

- Срок задаёт владелец через `PERSONAL_DATA_RETENTION_DAYS`.  
- В текущей версии **нет** гарантированного auto-delete job — это нужно честно отразить в политике и процессах.  
- Удаление заявок: вручную / скрипты сопровождения / будущая доработка.

---

## 7. Контент для реального клиента

Перед заменой demo-контента владелец предоставляет (если публикует claims):

- реальные проекты и фото с правами использования;  
- реальные отзывы (если публикуются);  
- реальные гарантии и их условия;  
- реальные цены / порядок расчёта;  
- лицензии / сертификаты — только при наличии;  
- оферту / договор — только если через сайт действительно заключается дистанционный договор.

Не публиковать вымышленные AggregateRating / отзывы / реквизиты «для SEO».

---

## 8. CRM и безопасность ops

- Задать уникальные `CRM_PASSWORD` и `CRM_SESSION_SECRET` (≥16 символов).  
- HTTPS, HTTP→HTTPS, заголовки безопасности задаются в приложении (`next.config.ts`); при необходимости дублировать в Nginx.  
- Rate limit заявок — **in-memory** на процесс Node. Для нескольких инстансов нужен общий store (Redis и т.п.) — рекомендация ops, не часть demo.
