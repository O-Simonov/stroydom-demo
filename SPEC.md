# SPEC — DEMO PROJECT 01: СТРОЙДОМ

**Тип:** демонстрационный проект для портфолио (не реальный клиент).  
**Ниша:** строительство загородных домов под ключ.  
**Условное название:** СТРОЙДОМ.

Цель демо — показать заказчику не «просто лендинг», а связку:

**Сайт → форма → API → база → Telegram → mini-CRM**

---

## 1. Продукт

Одностраничный лендинг строительной компании с калькулятором параметров дома, формой заявки, уведомлениями в Telegram и простой админ-страницей заявок `/leads`.

### Позиционирование на лендинге

- **Заголовок:** Строительство загородных домов под ключ  
- **Подзаголовок:** От проекта до сдачи готового дома  
- **CTA:** Рассчитать стоимость / Посмотреть проекты  

---

## 2. Стек технологий

| Слой | Технология | Зачем |
|------|------------|--------|
| Frontend + Backend | **Next.js 15 (App Router) + TypeScript** | Один проект: лендинг, API, CRM |
| UI | **Tailwind CSS** | Быстрая адаптивная вёрстка |
| Валидация API | **Zod** | Серверная валидация `POST /api/leads` (обязательна; клиентская её не заменяет) |
| БД | **SQLite + Prisma** | Локальная разработка и деплой на VPS |
| Уведомления | **Telegram Bot API** | Сообщение менеджеру о новой заявке |
| CRM-доступ | Env-пароль + httpOnly cookie-сессия | Защита `/leads` и CRM API |
| Деплой | VPS (SQLite) или позже serverless + внешняя БД | См. раздел Deployment |

Альтернативы (не берём в v1): отдельный Express, PostgreSQL сразу, полноценный Auth.js, CAPTCHA — избыточно для первого демо.

## 3. Архитектура

```
Посетитель
    ↓
Лендинг (Next.js pages/components)
    ↓
Форма заявки / калькулятор
    ↓
POST /api/leads
    ├─ Zod-валидация
    ├─ anti-spam (honeypot + rate limit)
    ├─ Prisma → SQLite (сохранение Lead)  ← успех заявки
    └─ Telegram Bot API (best-effort)     ← сбой не откатывает Lead
         ↓
Менеджер открывает /leads (mini-CRM, только после авторизации)
    ↓
Таблица заявок + смена статуса
```

### Поток создания заявки (`POST /api/leads`)

Строгий порядок:

1. **Валидировать** тело запроса через Zod (сервер). Клиентская валидация — только UX, не замена серверной.
2. Проверить **anti-spam**: honeypot; простой rate limit. CAPTCHA в v1 не использовать.
3. **Сохранить** `Lead` в БД со статусом `NEW`.
4. **Затем** попытаться отправить Telegram-уведомление.
5. Если Telegram недоступен / вернул ошибку:
   - сохранённая заявка **всё равно считается успешно созданной**;
   - ошибку Telegram **записать в лог**;
   - клиенту **не возвращать 500**, если запись в БД создана успешно (ответ `201`).
6. `500` — только если не удалось сохранить в БД (или иной критический сбой до/во время записи).

### Поток данных (обзор)

1. Клиент заполняет форму (или калькулятор + контакты).
2. Frontend может валидировать поля для UX и отправляет JSON на `POST /api/leads`.
3. API валидирует Zod → пишет `Lead` → best-effort Telegram.
4. Менеджер видит пуш в Telegram и/или таблицу на `/leads` (после входа).
5. Менеджер меняет статус заявки в CRM.

## 5. Backend / API

### `POST /api/leads`

Принимает JSON с полями формы. Серверная валидация — **Zod**.

Ответ:

- `201` — заявка создана в БД (даже если Telegram упал)
- `400` — ошибка валидации Zod
- `429` — rate limit
- `500` — критическая ошибка (например, БД); **не** из-за сбоя Telegram при уже сохранённом Lead

### `GET /api/leads`

Список заявок, сортировка по дате (новые сверху). Опционально фильтр по статусу.

**Требует авторизации CRM.** Без сессии — `401`.

### `PATCH /api/leads/[id]`

Смена `status` заявки.

**Требует авторизации CRM.** Без сессии — `401`.

### `POST /api/crm/login` / `POST /api/crm/logout`

Вход по `CRM_PASSWORD`, установка/сброс cookie-сессии.

## 7. Anti-spam (v1)

| Мера | Описание |
|------|----------|
| **Honeypot** | Скрытое поле формы; если заполнено — отклонить запрос (без создания Lead) |
| **Rate limit** | Простой лимит на `POST /api/leads` (например, по IP в памяти процесса) |
| **CAPTCHA** | **Не использовать** в v1 |

## 9. Mini-CRM `/leads` и безопасность сессии

### Доступ

- **`/leads` недоступен без авторизации** (редирект на логин или 401/страница входа).
- **`GET /api/leads`** и **`PATCH /api/leads/[id]`** также **требуют авторизации**.
- Без ролей, команд и сложной аналитики — только заявки.

### Cookie сессии CRM

| Флаг | Значение |
|------|----------|
| `httpOnly` | `true` (обязательно) |
| `sameSite` | `lax` |
| `secure` | `true` в production |

UI CRM: таблица ID, Клиент, Телефон, Услуга, Дата, Статус; смена статуса из UI.

| Сценарий | БД |
|----------|-----|
| Локальная разработка | **SQLite** (`file:./dev.db`) |

### Итоговая функциональность

**Публичная часть**

- адаптивный лендинг: hero, преимущества, каталог проектов домов, этапы, галерея, блок ценности, форма;
- калькулятор параметров дома (площадь, этажность, материал, комплектация) с переносом значений в форму заявки; денежная стоимость не рассчитывается;
- `POST /api/leads`: Zod-валидация на сервере, honeypot, rate limit по IP, Prisma → SQLite, затем best-effort Telegram, ответ `201`;
- `landingUrl` принимается только как корректный `http/https` URL;
- сквозной UTM-трекинг (`utm_source/medium/campaign/content/term`) и landing URL;
- `GET /api/health` — публичный liveness без раскрытия внутренних деталей.

**Mini-CRM `/leads`**

- вход по `CRM_PASSWORD`, подписанная cookie-сессия (HMAC SHA-256, 8 часов, httpOnly / sameSite=lax / secure в production);
- fail-closed: без CRM-переменных CRM недоступна, публичный сайт работает;
- `GET /api/leads` — только с сессией: последние 50, фильтр по статусу, поиск по имени/телефону/Telegram, `Cache-Control: no-store`;
- `PATCH /api/leads/[id]` — только смена `status`, Zod + проверка Origin, корректная обработка Prisma `P2025` → `404`;
- список, счётчики, фильтры, поиск, карточка заявки, empty state;
- адаптив: таблица на desktop, карточки на мобильном;
- DELETE, редактирование контактов, заметки, роли и пользователи — намеренно не реализованы.

**Production preparation**

- метаданные, OpenGraph, robots и sitemap через `NEXT_PUBLIC_SITE_URL` (домен не захардкожен);
- CRM закрыта от индексации (`noindex, nofollow`);
- `.env.production.example`, systemd- и Nginx-примеры в `deploy/`;
- persistent база вне каталога приложения (`/var/lib/stroydom/stroydom.db`);
- инструкции по backup/restore SQLite;
- документы портфолио: `CASE.md`, `PORTFOLIO.md`, `SCREENSHOTS.md`, `DEPLOY_VPS.md`.
