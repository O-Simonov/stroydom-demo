# Кейс: СТРОЙДОМ

Демонстрационный проект для портфолио. Компания вымышленная.

**Live:** [https://stroydom-project.ru](https://stroydom-project.ru)  
**Код:** [github.com/O-Simonov/stroydom-demo](https://github.com/O-Simonov/stroydom-demo)

## Контекст

Смоделирован типичный бизнес: строительство частных загородных домов. У такого заказчика обычно есть сайт-визитка, заявки разъезжаются по почте и мессенджерам, а менеджер не видит, откуда пришёл клиент и на каком этапе сделка.

## Задача

Показать не просто лендинг, а полный процесс получения и обработки обращения: от первого экрана до статуса в CRM, с публикацией в production.

## Решение

Одно Next.js-приложение закрывает весь цикл:

- коммерческий лендинг и каталог проектов;
- подбор параметров дома и форма заявки;
- API с валидацией и записью в базу;
- уведомление менеджера в Telegram;
- закрытая mini-CRM со статусами;
- размещение на VPS: Nginx, HTTPS, systemd, backup базы.

## User flow

1. Пользователь открывает сайт.
2. Смотрит предложение и проекты домов.
3. Выбирает параметры (площадь, этажи, материал, комплектация).
4. Оставляет имя и телефон.
5. API проверяет данные на сервере.
6. Обращение сохраняется в SQLite.
7. Telegram уведомляет менеджера (если бот настроен).
8. Лид появляется в `/leads`.
9. Менеджер меняет статус по ходу работы.

## CRM flow

```
NEW → CONTACTED → QUOTE_SENT → NEGOTIATION → WON / LOST
```

Исходные поля заявки из интерфейса не редактируются и не удаляются — меняется только статус.

## Что было реализовано

**Frontend.** Адаптивный лендинг, подбор параметров, форма с понятными состояниями, UTM и адрес страницы входа.

**Backend.** `POST /api/leads`, Zod, Prisma, honeypot, rate limit, Telegram best-effort (ошибка бота не откатывает заявку).

**CRM.** Пароль, HMAC-сессия, список, поиск, фильтры, счётчики, карточка лида, смена статуса, карточки на мобильном.

**Инфраструктура.** Ubuntu VPS, Nginx, systemd, Let's Encrypt, Certbot auto-renew, SQLite вне каталога кода, backup, `/api/health`, GitHub, SSH только по ключу, UFW.

## Что показал проект

Не коммерческие цифры, а инженерный результат:

- полный цикл «сайт → база → Telegram → CRM»;
- рабочий production с HTTPS;
- раздельные local и production-окружения;
- backup базы и health-check;
- базовая защита формы и CRM;
- интеграция с Telegram без потери заявки при сбое уведомления.

## Что можно развить в реальном проекте

Это возможные расширения, **не** реализованные в демо:

- PostgreSQL и несколько менеджеров с ролями;
- заметки и задачи по лиду;
- email-уведомления;
- Яндекс.Метрика и коллтрекинг;
- выгрузка в AmoCRM / Bitrix24;
- каталог объектов и простой CMS.

## Статус

Демонстрационный проект для портфолио. Не является сайтом действующей строительной компании и не содержит отчёта о продажах.
