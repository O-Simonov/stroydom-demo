# СТРОЙДОМ

Сайт строительной компании с калькулятором, приёмом заявок и mini-CRM.

## Тип проекта

Демонстрационный проект для портфолио.  
Компания «СТРОЙДОМ» вымышленная, контакты и заявки — тестовые.

## Задача

Показать не «просто лендинг», а полный цикл работы с обращением клиента:

```
Сайт → калькулятор → форма → API → база данных → Telegram → CRM
```

Типичная проблема малого бизнеса: заявки теряются между сайтом, почтой и мессенджерами,
а менеджер не понимает, откуда пришёл клиент и на каком этапе сделка.
Проект решает это end-to-end.

## Что реализовано

**Публичная часть**

- адаптивный лендинг (мобильные, планшет, desktop);
- каталог проектов домов с параметрами;
- калькулятор параметров дома — форма предварительного расчёта: площадь, этажность, материал, комплектация;
- форма заявки с переносом параметров из калькулятора;
- понятные состояния отправки: загрузка, успех, ошибка.

**Обработка заявки**

- `POST /api/leads` — серверная валидация через Zod (клиентская валидация её не заменяет);
- защита от спама: honeypot-поле и rate limit по IP;
- сохранение заявки в базу через Prisma;
- мгновенное уведомление менеджеру в Telegram;
- сбой Telegram не приводит к потере заявки — она уже сохранена;
- сквозной UTM-трекинг (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`) и landing URL.

**Mini-CRM `/leads`**

- вход по паролю, подписанная серверная сессия;
- список заявок, новые сверху;
- счётчики: всего / новые / в работе / продажи;
- фильтр по статусу и поиск по имени, телефону и Telegram;
- карточка заявки со всеми параметрами и UTM-источником;
- смена статуса: Новая → Связались → Расчёт отправлен → Переговоры → Продажа / Отказ;
- адаптив: таблица на desktop, карточки на мобильном.

## Технологии

| Слой | Технология |
|------|------------|
| Frontend + Backend | Next.js 15 (App Router), TypeScript |
| Вёрстка | Tailwind CSS |
| Валидация | Zod (runtime, на сервере) |
| База данных | SQLite + Prisma ORM |
| Уведомления | Telegram Bot API |
| Хостинг | VPS: Node.js + systemd + Nginx + Let's Encrypt |

Один проект содержит и сайт, и API, и CRM — это упрощает поддержку и снижает стоимость хостинга.

## Безопасность

- вся валидация входящих данных выполняется на сервере;
- `landingUrl` принимается только как корректный `http/https` URL;
- CRM закрыта подписанной cookie-сессией (HMAC SHA-256, срок 8 часов);
- cookie `httpOnly`, `sameSite=lax`, `secure` в production;
- пароль CRM сравнивается только на сервере, с защитой от timing-атак;
- отдельный rate limit на попытки входа;
- проверка Origin для операций, изменяющих данные;
- секреты (токен бота, пароль CRM, ключ подписи) существуют только на сервере и никогда не попадают в браузер;
- CRM закрыта от индексации поисковыми системами;
- удаление и редактирование заявок из интерфейса недоступно — исходные данные обращения защищены.

## Архитектура

```
Клиент
  │
  ├── Лендинг + калькулятор
  │        ↓
  │   POST /api/leads
  │        ├── Zod-валидация
  │        ├── honeypot + rate limit
  │        ├── Prisma → SQLite   ← заявка сохранена
  │        └── Telegram Bot API  ← best-effort, сбой не ломает заявку
  │
Менеджер
  │
  └── /leads/login → подписанная сессия → /leads
           ├── GET /api/leads          (список, фильтр, поиск)
           └── PATCH /api/leads/[id]   (только смена статуса)
```

## Результат

Готовый демонстрационный продукт: клиент оставляет заявку на сайте,
менеджер мгновенно получает уведомление в Telegram и ведёт сделку в CRM,
а источник обращения (реклама, соцсети, прямой заход) сохраняется автоматически.

Проект подготовлен к публикации на VPS: описаны systemd-сервис, конфигурация Nginx,
HTTPS-сертификат, персистентное хранение базы и процедура резервного копирования.

Коммерческие показатели намеренно не приводятся: это демонстрационный проект,
а не отчёт по реальному клиенту.
